# AB#1668014

## Executive Summary

auro-carousel's help text, the descriptions people see in code editors, the API docs and the README, now follows Auro's content guidelines, and its machine-readable description now passes Auro's strictest automated check when run locally. The descriptions were checked against what the component actually does, and the wrong ones were fixed. Two pieces are still open: the check isn't yet part of the build, and the description file isn't yet included in the published package. See Ticket Completeness. Ticket: [AB#1668014](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1668014)

## The Problem

auro-carousel's published description didn't follow Auro's writing guidelines, and some of it was wrong. It claimed the arrows always show when they stay hidden on small screens. It said a label setting was ignored when it wasn't. It described a "selected node" being centered when the behavior is to scroll the first item marked as selected. Several example pages used a deprecated way of naming the carousel, so people copying them got a console warning. The machine-readable description also had four problems that Auro's strict check flags: three option names weren't in the lowercase form HTML actually uses, and one content slot was marked as deprecated with no replacement named.

## Root Cause

- `src/auro-carousel.js`: JSDoc was terse or incorrect. The class description lacked a first sentence that stands alone, key capabilities, an example and a `@summary`. `label` used `DEPRECATED -` with no `@deprecated` tag. The `displayArrows` description ignored the `sm` breakpoint (the buttons are `display: none` below it).
- `docs/partials/api.md` carried the same wrong claims, plus title-case headings. The `aria-label` note said the host attribute was "ignored in favor of" the slot, but the component never reads it.
- `apiExamples/*` used the deprecated `label` or had no name at all, and repeated dates.
- `firstUpdated` warned whenever `label` was empty, even when the `ariaLabel` slot was set.
- `centerSelected` was declared as a `String` property but is only ever read with `hasAttribute`.
- `displayArrows` and `scrollDistance` had no explicit `attribute` name, so the manifest published them in camelCase.
- The `ariaLabel` slot description said "the deprecated `label` attribute". The CEM tooling reads that prose as the slot itself being deprecated.

## The Fix

- Rewrote the class JSDoc (first sentence, **Key capabilities**, `@example`, `@summary`), slots, CSS part, events and public and private methods per the guidelines. Added `@throws` to `centerElement`, a `Deprecated:` / `@deprecated` pair for `label`, and `@cssprop` tags for the two `--ds-auro-carousel-gradient-color-*` properties.
- Corrected the inaccurate claims in the JSDoc and `docs/partials/api.md`, and the prose in the description, use-cases and custom-registration partials.
- Every example now names the carousel with the `ariaLabel` slot. Dates are sequential, and the slot examples use real names ("Show earlier dates").
- The label warning now fires only when neither `label` nor the `ariaLabel` slot is set.
- Removed `centerSelected` from `static properties` and documented it with `@attr {boolean} centerselected`.
- Added explicit `attribute: "displayarrows"` and `attribute: "scrolldistance"`. Lit already lowercases attribute names, so runtime behavior is unchanged.
- Reworded the `ariaLabel` slot description so it no longer contains the word "deprecated".
- Rebuilt with `npm run build`, so `README.md`, `docs/api.md` and `custom-elements.json` reflect the changes.

## Why This Works

Each description was checked against the code that decides it (source, styles and the generated CEM), so the docs match behavior. The label warning matches the documented way to name the carousel. The explicit lowercase attribute names match how HTML binds attributes, and the camelCase names stay in `fieldName`. Removing the word "deprecated" from a live slot's description stops the tooling from flagging the replacement as deprecated.

## Outcome

Descriptions, API docs and examples follow the guidelines and are accurate. `auro cem-check --strict` reports no violations locally, the build succeeds, and the existing 16 unit tests pass. A follow-up bug, [AB#1670504](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1670504), covers a separate focus and spacing issue found along the way, where label elements count as the first and last child. The check still isn't part of the build, and the description file isn't yet in the published package.

## Learnings

- Don't use the word "deprecated" in the description of an item that isn't deprecated. The CEM tooling reads prose, and it flagged the replacement slot.
- Set Lit's `attribute` option explicitly when the manifest needs lowercase names, because the analyzer otherwise publishes the property name.
- Check how the code reads an option before choosing how to declare it. `centerSelected` was declared as a property but only works as an attribute.
- Documented guidance and examples drift apart. Every example used a deprecated or missing carousel name until a full review caught it.
- Named slot elements count as light DOM children, so code and CSS that assume `firstElementChild` or `:first-child` break when slots are used (AB#1670504).
- A deprecation needs both the `Deprecated:` line and the `@deprecated` tag so the CEM carries a migration message.

## Iterations That Didn't Work

- The first review pass left the label warning as is and documented it as an open question. It still fired for every example that used the documented `ariaLabel` slot, so the check was changed.
- Documenting `centerSelected` as a `String` property was reverted, because it's only ever an attribute.
- The first `ariaLabel` slot description named the deprecated `label` attribute, which made the strict check flag the slot itself as deprecated. It was reworded.
